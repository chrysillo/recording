## Findings

1. **Leaving the app during a rename, delete or Make louder crashes the process, and with it any take in progress** (high, core)
   `MainActivity.kt:323` (`io.shutdown()` in `onDestroy`); throws from `MainActivity.kt:241`, `:265`, `:400` and `:405`.
   - Back on the home screen calls `finish()`, so `onDestroy` shuts down `io` while a job may still be running on it.
   - When that job ends it calls `listClips()`, which calls `io.execute` on the shut-down executor. That throws `RejectedExecutionException` on the executor's thread.
   - In `louder` and `guardedIo`, the call that throws sits in the `catch` block (or is reached again from it), so nothing catches it and Android kills the process.
   - `RecorderService` runs in the same process. A take recording in the background dies too, and an M4A or Opus take can't be recovered (finding 4).
   - Repro: start a take, open the app, run Make louder on a long clip, press Back before it finishes.

   *Fix (S):* move the executor out of the activity, for example to an `object` or a lazily created process-wide single thread, and stop shutting it down. Work like Make louder should finish even after the activity has gone. Each `js()` already checks `isDestroyed`. Then check by hand: the repro above should leave the take running and the louder copy in the list.

2. **The service can be destroyed while a take is still opening, leaving the mic running with no notification** (medium, core)
   `RecorderService.kt:96`, `:159-163`, `:218-221`.
   - A second `ACTION_START` arriving while `recording` is true but `recorder` is still null calls `stopSelf()`.
   - `onDestroy` then stops only `recorder`, which is still null, and lets `io` finish `open()`.
   - `open()` then posts `recorder = rec` to a destroyed service. The `AudioRecord` thread keeps recording with no foreground service, and the file stays pending.
   - The window is narrow (the page's `busy` flag and `MainActivity.startRecording`'s guard block most double starts), but nothing in the service itself prevents it.

   *Fix (S):* drop the `else if (recorder == null) stopSelf()` branch, since a second start while opening should do nothing. Add a `destroyed` flag set in `onDestroy`, and in `open()`'s `main.post` call `rec.stop()` if it's set.

3. **Encoders, MediaStore and the service have no instrumented tests** (medium, core; was high)
   `Encoders.kt`, `ClipStore.kt`, `RecorderService.kt`, `Transcoder.kt`, `Louder.kt`.
   - The app now runs on a phone: the README and `recorder.js:5` cite a Sony Xperia 1 VI's mics and levels. So the "never run" part of last time's finding is fixed.
   - What's left is that each change to the encoders or `ClipStore` can only be checked by hand.

   *Fix (M):* add `androidTest` round-trip tests: encode a synthetic sine through `WavEncoder` and `CodecEncoder` (AAC, Opus) into a temp file, read it back with `MediaExtractor` and check the duration is within 50 ms, plus the rate and channels. Also `Louder.make` on a quiet WAV, checking that the new clip peaks near −1 dBFS.

4. **M4A and Opus takes are lost if the process dies mid-take** (medium, core; carried, in Known debt)
   `ClipStore.kt:205-210`. This is unchanged, but finding 1 is a realistic way for the process to die. Fix finding 1 first.
   *Fix (M):* record every take to WAV in app storage and encode to the chosen format on Save. Alternatively, write fragmented MP4.

5. **`MainActivity` has six jobs** (medium; worse)
   `MainActivity.kt`, 416 lines: WebView host and theme, permissions, clip operations and consent, sharing, Make louder, and the bridge. Make louder landed here, as last time predicted for new features.
   *Fix (S):* this goes naturally with finding 1. Move the executor and the long jobs (`share`/voice note, `louder`, rename/delete with consent) into a `ClipActions` class that reports back through a small callback. That leaves the activity as the host and the bridge as a thin adapter.

6. **WAV takes longer than about 6 hours in stereo get a header that can't describe them** (low, core)
   `WavHeader.kt:11`, `Encoders.kt:57`. The header is clamped at 4 GB, which is 6.2 h in stereo or 12.4 h in mono, while the wake lock allows 12 h. Data past that point is written, but most players stop at 4 GB.
   *Fix (S):* when `bytes` nears the limit, save the take and start the next one (`Recording7`, `Recording8`), or stop with a message.

7. **A half-written Make louder WAV is published after a crash** (low)
   `ClipStore.kt:206-209` and `Louder.kt:32`. The louder copy is created pending like a take. If the process dies mid-copy, `repairUnfinished` fixes its header and publishes a truncated "… louder.wav".
   *Fix (S):* don't repair names ending in " louder" (or keep a list of pending take URIs, which finding 9 needs anyway).

8. **A delete waits while the app is in the background** (low; carried)
   `clips.js:139-156`. Unchanged.
   *Fix (S):* commit the pending delete from a `visibilitychange` handler when the page is hidden.

9. **Android 10 doesn't repair WAV takes cut short** (low; carried, in Known debt)
   `ClipStore.kt:219`. Unchanged.
   *Fix (S):* remember the pending URI in SharedPreferences when a take starts.

10. **Docs drift** (low)
    - The README's Known debt says "Untested on a phone", but the app has run on an Xperia 1 VI. This run updates it.
    - `app/build.gradle.kts:13`: `versionName = "0.1"`, while the README says v0.2.
    - `RecorderService.kt:26`: the KDoc mentions "a Stop button"; the notification now has Pause/Resume, Discard and Save.

    *Fix (S).*

## Security
security.py's results compared with last time:
- **Permissions:** the same 8 as last time, each used. The mic is asked for on the first tap, and the rest once alongside it. The mic is open only inside `RecorderService`, and since pause it's released while paused (`Recorder.kt:78`), so the privacy indicator goes off.
- **Components:** still only the launcher is exported. `RecorderService` isn't exported, and its notification `PendingIntent`s are immutable and explicit. `ShareProvider` isn't exported, is read-only, and serves plain names only.
- **WebView:** unchanged. JavaScript is on, file and content access are off, and navigation is limited to bundled assets. There's no debugging flag.
- **Bridge:** 16 methods, up from 12. The new ones are `pauseRecording`, `resumeRecording` and `discardRecording` (no arguments, no-ops when not recording) and `louder(id)` (listed ids only).
- **Data:** recordings live in shared storage, and app storage holds only settings. `allowBackup="true"` is still right. Nothing is logged.
- **Release:** R8 is on.
- **Supply chain:** unchanged. The only dependency is JUnit, and the Gradle wrapper has a checksum.

No `docs/security` report yet.
