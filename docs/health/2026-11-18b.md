## Findings

1. **The recording path has never run** (high, core)
   `Recorder.kt`, `Encoders.kt`, `ClipStore.kt`, `RecorderService.kt`, `Transcoder.kt`. MediaCodec, MediaMuxer, MediaStore pending files and the foreground service type all behave differently from phone to phone. A mistake here loses takes, and no JVM test can reach this code.
   *Fix (M):* first, the phone checklist in the README's Known debt and ROADMAP's Next: each format, screen off mid-take, unplugging a USB mic mid-take, a WhatsApp voice note, and Files › Recordings. Then add `androidTest` instrumented tests that encode a synthetic sine through `WavEncoder`/`CodecEncoder` into a temp file and read it back with `MediaExtractor` (duration within 50 ms, sample rate, channel count).

2. **M4A and Opus takes are lost if the process is killed mid-take** (medium, core)
   `ClipStore.kt:205-210`. The MP4 and Ogg muxers write their index at the end, so a pending M4A has to be deleted. The foreground service makes a kill unlikely, but the default format is the one that can't be recovered. This is listed in Known debt.
   *Fix (M):* either record every take to WAV in app storage and encode to the chosen format on Stop (a few seconds' wait for long takes), or write fragmented MP4 by hand. The first is simpler and also makes trimming easier later.

3. **`MainActivity` has five jobs** (medium)
   `MainActivity.kt` (390 lines): WebView host and theme, permissions, clip operations and consent dialogs, sharing, and the bridge. Each new feature (trim, pause) will land here too.
   *Fix (S):* move sharing (`share`, `send`, the voice-note job) into a `Sharing` class and the clip operations (`listClips`, `handle`, consent) into a small `ClipActions`, leaving the activity as the host and the bridge as a thin adapter.

4. **A delete waits while the app is in the background** (low)
   `clips.js:135-152`. WebView timers pause in `onPause`, so a clip deleted just before leaving the app is only removed on return; meanwhile it's still in the Files app. Nothing is lost, and Undo still works on return.
   *Fix (S):* commit any pending delete from a `visibilitychange` handler when the page is hidden.

5. **Android 10 doesn't repair WAV takes cut short** (low)
   `ClipStore.kt:219`. API 29 can't query pending files, so a WAV left pending there stays hidden until the system cleans it up after a week. Listed in Known debt.
   *Fix (S):* remember the pending URI in SharedPreferences when a take starts and clear it on publish; on start, repair that one URI.

6. **Theme stored twice** (low, carried over)
   `MainActivity.kt:95`, `store.js`. Unchanged and still justified. The recording settings now go through one JSON config, as suggested last time.

## Security
security.py versus the baseline:
- **Permissions:** none before; now `RECORD_AUDIO`, `POST_NOTIFICATIONS`, `READ_MEDIA_AUDIO`, `READ_EXTERNAL_STORAGE` (≤32), `WRITE_EXTERNAL_STORAGE` (≤28), `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MICROPHONE` and `WAKE_LOCK`.
  - Each is used.
  - The dangerous ones are asked when the record button is first tapped. Only the mic, plus storage on Android 8–9, is required; the rest are asked once and the app works without them.
  - The mic is only open inside `RecorderService`, with its notification showing.
- **Components:** the launcher is still the only exported component. `RecorderService` and `ShareProvider` are not exported. The provider grants per-URI access, serves only plain file names from `cache/share/`, and is read-only.
- **WebView:** unchanged. JS on, file and content access off, navigation limited to bundled assets.
- **Bridge:** 12 methods, all called by the page.
  - Ids are accepted only if they were in the last list sent.
  - The config is re-validated in `RecordConfig.of`, and names go through `ClipNames.rename`.
  - `seek` checks `isFinite` and clamps.
  - String arguments are capped at 2,000 characters.
- **Data:** recordings live in shared storage (the user's own files, outside app backups). App storage holds only settings, so `allowBackup="true"` stays. Nothing is logged.
- **Release:** R8 is on. The `@JavascriptInterface` names survive shrinking (checked in the release dex).
- **Supply chain:** unchanged. No dependencies besides JUnit; the wrapper has a checksum.

No earlier `docs/security` report.
